# Building Syndic on macOS

Syndic is a responsive RSS/Atom feed reader built with Qt 6 and KDE Frameworks 6.
It targets Linux desktop and Android, but it also builds and runs on macOS, where
the build produces a self-contained `Syndic.app` that runs on any Mac without
Homebrew, Qt, or the KDE Frameworks installed.

## Quick start

```sh
brew install qt extra-cmake-modules pkg-config
./macos/build.sh
open dist/Syndic.app
```

The first run takes roughly ten minutes: it clones and builds five KDE
Frameworks from source before building Syndic itself. Subsequent runs reuse
those builds.

## What the build does

`macos/build.sh` runs three steps, each of which can be run on its own with
`--step`:

| Step | What it does |
|---|---|
| `deps` | Clones the pinned KDE Frameworks into `deps/`, patches them, builds them, installs them into `deps/kf6-prefix` |
| `app` | Configures and builds Syndic against that prefix into `build/` |
| `bundle` | Assembles, relocates, slims, and signs `dist/Syndic.app` |

Useful invocations:

```sh
./macos/build.sh --step bundle          # re-assemble the bundle only
./macos/build.sh --step app --step bundle
./macos/build.sh --clean                # discard deps/kf6-prefix, build/, dist/
./macos/build.sh --jobs 12 --build-type Debug
./macos/build.sh --dmg                  # also produce dist/Syndic.dmg
./macos/build.sh --sign "Developer ID Application: Your Name (TEAMID)"
```

Everything version-specific lives in `macos/config.sh`: the KDE Frameworks tag,
the package list and its build order, the patches, the bundle name, the
deployment target, and the list of Qt components to prune. Nothing is pinned
anywhere else.

## Bundle metadata and the app icon

The `Info.plist` is generated by CMake, not by the shell script.
`src/CMakeLists.txt` sets `MACOSX_BUNDLE_INFO_PLIST` to `macos/Info.plist.in`
and the `MACOSX_BUNDLE_*` properties that fill it in (bundle name, identifier,
icon, copyright); the version keys come from `PROJECT_VERSION` and
`LSMinimumSystemVersion` from `CMAKE_OSX_DEPLOYMENT_TARGET`, which `build.sh`
passes on the cmake command line. The plist is therefore already correct in
`build/src/syndic.app`, and the `bundle` step just copies it along.

The app icon is pre-generated and committed at `macos/syndic.icns`, and CMake
copies it into `Contents/Resources`. Nothing rasterizes it at build time. If
the icon ever changes, regenerate it from
`data/icons/sc-apps-com.rocksandpaper.syndic.svg` with any SVG rasterizer that
preserves transparency (macOS `qlmanage` and `sips` both do not — `rsvg-convert`
or Inkscape work) into a `syndic.iconset` directory of
`icon_<N>x<N>[@2x].png` slices at 16, 32, 128, 256 and 512 points, then:

```sh
iconutil -c icns syndic.iconset -o macos/syndic.icns
```

## Dependencies

Only five KDE Frameworks are needed:

| Package | Needed by |
|---|---|
| KCodecs | KSyndication |
| KConfig | Syndic (settings) |
| KSyndication | Syndic (feed parsing) |
| Breeze Icons | Syndic (icon theme) |
| Kirigami | Syndic (UI framework) |

All are built from the tag in `KF6_VERSION` (currently `v6.12.0`). Qt and ECM
come from Homebrew; the KDE Frameworks are not packaged for macOS, so they are
built from source.

### Why the list is this short

On Linux, Syndic uses the `org.kde.desktop` Qt Quick Controls style. That style
lives in qqc2-desktop-style, which drags in KIconThemes, KColorScheme,
KArchive, KWidgetsAddons, KGuiAddons, KCoreAddons, KQuickCharts and Sonnet — a
long tail of frameworks that exist to make Qt look like Plasma. On a Mac that
is the wrong look anyway, so `main.cpp` selects Qt's native `macOS` style there
instead, and none of that tail gets built or shipped.

Kirigami logs `Failed to find a Kirigami platform plugin for style "macOS"` at
startup and falls back to its built-in defaults. That message is expected.

## Things that bite on macOS

These are the non-obvious problems the scripts work around. They are worth
knowing about if you change the build.

**KDEInstallDirs and install names.** KDE's `KDECMakeSettings` derives
`CMAKE_INSTALL_NAME_DIR` from the prefix as it stands at *configure* time. On
macOS, where there is no system KDE prefix to detect, that value ends up empty,
so every library gets an install name like `/lib/libKF6ConfigGui.6.dylib` — a
path that does not exist and cannot be rewritten reliably. Installing with
`cmake --install --prefix` does not help, because by then the install names are
already baked in. The fix is to pass `-DCMAKE_INSTALL_PREFIX` at configure
time, which the build script does. `normalize_install_names` then repairs any
stragglers.

**Qt is newer than the frameworks.** Homebrew tracks Qt aggressively (currently
6.10), while KF6 6.12.0 was released against Qt 6.7–6.8. Qt 6.10 dropped a
transitive `#include <QElapsedTimer>` that Kirigami relied on, so
`macos/patches/kirigami-qt610-elapsedtimer.patch` adds it back. Patches live in
`macos/patches/` and are listed in `KF6_PATCHES`; they are re-applied on every
run against a clean checkout of the pinned tag, so the tree is reproducible even
if a previous run left it dirty.

**macdeployqt only knows about Qt.** It handles Qt's frameworks, plugins and QML
modules, and nothing else. The KDE libraries, the KF6 QML modules and the KF6
plugins are staged into the bundle by hand afterwards, and then
`macos/relocate.py` rewrites every load command.

## How the bundle is made self-contained

`macos/relocate.py` walks every Mach-O file in the bundle, copies in any library
that still points outside it, and rewrites the load commands to
`@executable_path`-relative form. It repeats until it reaches a fixed point, so
a library pulled in on one pass has its own dependencies resolved on the next.

Two extras matter:

- **Garbage collection** (`--gc`). macdeployqt deploys entire plugin categories
  regardless of whether the app can use them. `PRUNE_PLUGIN_DIRS` and
  `PRUNE_QML_MODULES` in `config.sh` drop the ones a feed reader has no use for
  (Qt3D scene parsers, the PDF viewer), and the collector then deletes the
  heavyweight libraries those plugins were the only users of — assimp and QtPdf,
  about 32 MB. Because reachability is computed rather than hardcoded, pruning a
  plugin is all you need to do; the libraries follow.

- **Verification.** The final pass fails the build if anything in the bundle
  references a path outside of it, or has a dangling bundle-relative reference.
  System libraries under `/usr/lib` and `/System` are the only things allowed
  through. You can re-check an existing bundle at any time:

  ```sh
  python3 macos/relocate.py dist/Syndic.app --verify-only
  ```

The bundle also carries a `qt.conf` that sets `Prefix = .`, which stops Qt from
finding a Homebrew installation on the build machine and masking the bundled
copies — the failure mode where a bundle works everywhere except a clean Mac.

The Breeze icon theme is *not* copied into the bundle. `BreezeIcons::initIcons()`
unpacks it into the `:/icons` Qt resource that is compiled into
`libKF6BreezeIcons`, so the 60 MB on-disk copy of the same theme would be dead
weight.

The result is about 165 MB, ad-hoc signed by default. Pass `--sign` with a
Developer ID to sign for distribution.

## Verifying a build

The build is only trustworthy if it runs somewhere the build tree does not
exist. The strongest local check is to hide the framework prefix and launch the
bundle from outside the source directory with a scrubbed environment:

```sh
cp -R dist/Syndic.app /tmp/
mv deps/kf6-prefix deps/kf6-prefix.hidden
env -i HOME="$HOME" PATH=/usr/bin:/bin /tmp/Syndic.app/Contents/MacOS/syndic
mv deps/kf6-prefix.hidden deps/kf6-prefix
```

If it starts and loads its UI, nothing is leaking in from the build machine.

## Known limitations

- **QReadable is disabled.** The build passes `-DWITHOUT_QREADABLE=1`, so the
  reader view feature is not available. QReadable is a separate project and
  would need to be built from source and added to `KF6_PACKAGES` to enable it.
- **Not notarized.** `--sign` handles signing, but notarization
  (`xcrun notarytool`) is not wired up, so a distributed build will still be
  gatekeeper-quarantined on other machines.
- **Universal binaries are not built.** The bundle is built for the host
  architecture only.
